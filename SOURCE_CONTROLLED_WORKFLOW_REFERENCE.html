Nilavaram Source-Controlled Workflow Reference

Keep this page open on one monitor while editing the project in VS Code on the other monitor.

Prepared implementation: Popup guidance is source-controlled in VS Code. Apps Script receives the changes through clasp push. Firestore remains responsible for live controls and audit information, while OneDrive stores uploaded documents and evidence.

Quick summary

  • Edit guidance in the separate menu-named HTML file for that window.
  • ModuleGuideSources.html is only the registry that includes the separate menu-named files.
  • Prepared source-controlled guides with reviewed content are Life Timeline, Business Records and Permanent Records.
  • Every current visible menu item now has a separate menu-named HTML template.
  • Template files remain inactive until their content is reviewed and sourceReady is changed to true; existing fallback guidance is preserved meanwhile.
  • The internal ID identity-immigration is retained for compatibility but displays Permanent Records.
  • The existing hardcoded guidance remains as a fallback, so existing content is not lost.
  • Edit the left-side menu in Setup.js, inside setupNavigation_().
  • Keep stable IDs and module IDs unless a deliberate migration is required.
  • Use clasp push to send VS Code changes to Apps Script.
  • Test in the Apps Script /dev deployment before production.
  • Apps Script or Firestore edits do not automatically return to VS Code.
  • Copy any temporary live change back into the source files if it should be kept.
  • Do not place passwords, tokens, private keys or uploaded document contents in source files.

Popup guidance editing

For the complete list of current left-menu entries, stable module IDs, shared-popup relationships and filenames, open MenuFileCatalog.html. The cleaned catalog contains 80 unique menu-item entries and 71 distinct popup modules. Fourteen exact duplicate source definitions were removed from the retired Accounting Wizard block.

Edit the separate menu-named guide file for the window in VS Code:

  • LifeTimeline.html
  • BusinessRecords.html
  • PermanentRecords.html

ModuleGuideSources.html is the include registry. Normally you do not edit it when changing popup text.

Available guide IDs

  • life-timeline — Life Timeline
  • business-records — Business Records
  • identity-immigration — compatibility ID that displays Permanent Records

For the other current menu destinations, open the matching file listed in MenuFileCatalog.html. Complete its module-specific text, review it, and change sourceReady: false to sourceReady: true only when it is ready to replace the fallback.

Editable fields in each guide

  • purpose — what the window is for
  • source — where information and documents come from
  • display — what the user will see
  • steps — numbered use instructions
  • learn — important explanations and rules
  • dos — recommended actions
  • donts — warnings and prohibited actions
  • status — current implementation status

Popup editing steps

  1. Open the related menu-named HTML file in VS Code.
  2. Find the guide object for the popup.
  3. Edit only the text or list items that need to change.
  4. Save the file.
  5. Review the VS Code diff.
  6. Run the focused syntax checks.
  7. Run clasp push.
  8. Open the Apps Script /dev test deployment.
  9. Open the relevant left-menu item and check the popup.
  10. Test the affected role and selected client/business authorization context.
  11. Update production only after the /dev test succeeds.

Left-side menu editing

The source of truth is:

Setup.js → setupNavigation_()

Menu properties that may be edited

  • label — visible menu name
  • description — menu explanation
  • order — position within the parent
  • parentId — parent group or submenu
  • level — menu depth
  • roles — permitted roles
  • enabled — whether the item is shown
  • moduleId — module opened by the item

Rename a menu item

Change the visible label:

label: 'Business Records'

For example:

label: 'Business Information'
  • Keep the existing internal id.
  • Keep the existing moduleId unless a deliberate migration is required.
  • Keep the popup title and menu label consistent.

Move a menu item

Update the item's parent, depth and position:

parentId: 'assets-estate',
level: 2,
order: 30
  • Change parentId to select another parent group.
  • Change level to match the new menu depth.
  • Change order to place the item correctly among its siblings.

Hide or retire a menu item

Do not simply delete the old Firestore document. Stale navigation documents are not automatically deleted during a rewrite.
  1. Remove the item from the active source definition.
  2. Add an explicit disabled retirement record in the setup/reset path.
  3. Set enabled: false.
  4. Increase NILAVARAM_NAVIGATION_VERSION.
  5. Run clasp push.
  6. Run the owner-only navigation reset or rewrite in Apps Script.
  7. Reload the /dev deployment and verify the menu.

Four requested menu tasks

  1. Rename: edit the item's label in Setup.js.
  2. Delete/retire: disable the item with enabled: false and keep an explicit retirement record; do not silently delete its Firestore document.
  3. Re-position: edit order; to move it to another group also edit parentId and level.
  4. Save: save Setup.js in VS Code, increase NILAVARAM_NAVIGATION_VERSION, run clasp push, and run the owner-only navigation rewrite so Firestore receives the source definition.

There is no technical mechanism for Apps Script or Firestore to write files back into your VS Code workspace automatically. If you make a temporary live edit in the Developer Console, copy the final values back into Setup.js before treating the change as permanent.

Recommended commands

node --check Setup.js
node --check Code.js
node --check Development.js
clasp push
  • Run the checks from the repository folder.
  • Review the changed files before pushing.
  • Use the /dev deployment for testing.
  • Do not deploy to production until the affected popup and menu have been tested.

How Apps Script changes get back into VS Code

  • Apps Script changes do not automatically synchronize back to VS Code.
  • Direct Developer Console or Firestore edits should be treated as temporary testing changes.
  • Copy the final menu values back into Setup.js.
  • Copy the final window text back into the related menu-named HTML file.
  • Save the files in VS Code.
  • Run clasp push again.
  • VS Code remains the permanent source of truth.

OneDrive decision: Popup HTML is not fetched live from OneDrive. Static guidance stays in source-controlled Apps Script HTML files. OneDrive is used for uploaded documents and evidence, not executable or rendered popup code.

Important safety rules

  • Never put passwords, OAuth tokens, private keys or service-account secrets in source files.
  • Never put uploaded document contents in popup guide source.
  • Static popup guidance is not an authorization mechanism.
  • Apps Script server-side authorization remains authoritative.
  • Keep the selected client and business as authorization context where the application requires it.
  • Preserve audit logging and the existing role and permission model.
